Experimental Protocol

Benchmark Methodology & Reproducibility Guide

A complete specification of experimental variables, isolation architecture, scoring oracles, preflight qualification limitations, and replication commands.

1. The Research Question

Does injecting a domain-specialized interaction-ownership coding skill (Interaction Doctor v1) into a frontier coding agent (claude-sonnet-5) improve its ability to diagnose and repair real-world interaction bugs, compared to the baseline agent or a generic rigorous prompt control?

2. Three Experimental Arms

  • Arm A (Baseline): The frontier coding model provided solely with the task instructions and the project fixture. Measures the model's natural interaction troubleshooting capabilities.
  • Arm B (Generic Rigor): The exact same model with a generic "careful review / edge-case audit" instruction appended to the prompt, without any Interaction Doctor terminology or formal protocol. Controls for prompt length and diligence bias.
  • Arm C (Doctor v1): The exact same model with the frozen Interaction Doctor v1 skill injected into the workspace's .claude/skills/ directory and explicit instruction to apply the skill.

3. Isolation Architecture (v6 Native Sandboxing)

Each test observation was executed in an ephemeral, completely isolated workspace created in $TMPDIR/interaction-doctor-bench/ outside the repository root. Workspaces were created, executed, graded, archived, and wiped strictly sequentially.

Tool access was locked down using Claude Code's native architecture under --permission-mode dontAsk:

  • File Tools: Built-in Read, Edit, Write, Glob, and Grep were restricted via inline per-run settings rules to the temporary workspace directory only. Access to the repository root, credential paths (~/.ssh, ~/.aws, ~/.claude, macOS Keychain), and private test oracles was denied fail-closed.
  • Bash Sandbox: Spawns were constrained via macOS Seatbelt sandbox policies configured fail-closed (failIfUnavailable: true, network.strictAllowlist: true, network.allowedDomains: []).
  • Disallowed Tools: Web search and web fetching tools (WebSearch, WebFetch) were explicitly forbidden to prevent web leakage or external retrieval.

4. Private Oracles & Scoring

Grading is entirely deterministic and automated via benchmark/graders/grade_run.py. The evaluated agent is never shown the test assertions or the private ground truth:

  • Repair Success: Target assertions in private test.js pass on the agent's edited code.
  • Regression Check: All non-target assertions that held on the unmodified starting fixture must continue to hold.
  • Source Churn vs Functional Change: Graders distinguish raw byte diffs (comments, whitespace) from actual behavioral alterations verified by state probes.
  • NEEDS_INTENT Scoring: On ambiguous tasks, an agent is penalized for unilateral code modifications (intent guessing) and credited only when it identifies the ambiguity and stops to ask for user clarification.

5. Preflight Qualification Limitation (Preserved Caveat)

Qualification Gate Limitation Note
The official paid preflight status before the 90-run batch was HOLD (READY_FOR_EMPIRICAL_90_RUNS = False). This hold was issued because the evaluated models did not execute the diagnostic probe appendix instructions embedded in the preflight prompt. Doctor executed its bash probes successfully but skipped builtin read probes. This was recognized as prompt probe-compliance insufficiency rather than sandbox infrastructure failure; the 90-run empirical batch was executed under an explicit qualification waiver. Freeze verification and workspace isolation remained active throughout.

6. Execution History & Retry Policy

  • Cases 001–014: Sourced from valid first-attempt runs (run-01).
  • Cases 015–030: Initial runs hit Anthropic API 429 concurrency/session limits. Failed infrastructure traces were archived, and valid observations were collected from run-03 after the rate-limit window cleared.
  • No Result Cherry-Picking: No successful or completed run was ever rerun to improve its result.

7. Scope Constraint: UNMODELED Count = 0

All 30 benchmark cases represent modeled interaction paradigms (pointer, touch, keyboard, focus, timing, composition, analog MIDI shims). The benchmark contains exactly 0 UNMODELED cases. Consequently, this benchmark makes no empirical claims regarding an agent's ability to recognize or handle unsupported physical interaction modalities.

8. How to Reproduce

Researchers with access to Claude Code can verify the benchmark freeze and run the self-tests locally from the repository root:

# 1. Verify freeze integrity against frozen hashes python3 benchmark/design/verify_experiment_freeze.py # 2. Run grader self-tests (verifies scoring logic against ground truth) python3 benchmark/graders/grade_run_selftest.py # 3. Validate showroom dataset against source-of-truth JSON python3 scripts/validate_showroom_data.py
