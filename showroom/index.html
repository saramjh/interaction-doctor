Empirical Evaluation Dossier

A coding-agent skill experiment that failed to justify its cost.

A 30-case, 90-run controlled benchmark measuring interaction-defect diagnosis, repair, and ambiguity handling on frontier models.

The specialized Interaction Doctor skill provided zero measured repair advantage over the baseline model, nearly doubled token expenditure (~1.91×), and more than doubled latency (~2.44×). The skill has been discontinued. The benchmark is preserved as an independent research asset.

Why Did Doctor Only Stop on 011 and 016?

In case-011-shared-canvas-bifurcation and case-016-swipe-left-double-bound, the conflict directly manifested as two conflicting event handlers attached to the same DOM target. Doctor's ownership graph extraction explicitly flagged the collision and triggered the protocol's NEEDS_INTENT disposition.

Conversely, on case-004, case-010, case-013, and case-019, the ambiguity stemmed from lifecycle scoping or environmental defaults rather than direct simultaneous event bindings. Despite possessing the skill prompt, the model rationalized a 'standard' resolution and edited the files anyway.

Engineering Postmortem

Why Productization Failed: Three Architectural Dead Ends

When early smoke tests revealed that always running Interaction Doctor doubled costs with zero repair benefit, engineering explored three separate mitigation architectures to selectively invoke the skill. All three failed.

1. The Universal Semantic Eval Gate Problem

Hypothesis: Place a fast, cheap upstream classifier prompt in front of the model to decide whether an incoming task contains an interaction-ownership problem before loading the heavy skill.

Why it failed: Cascading classifiers have asymmetrical risk. If the gate has even a 10% false negative rate, it permanently locks out the downstream specialist from ever seeing the task. Tuning the gate for zero false negatives forced its recall so wide that it triggered on virtually every UI edit, returning total costs right back to 1.9×.

2. The Self-Routing Failure

Hypothesis: Give the baseline agent a concise tool or skill description and let the model self-route when it gets stuck or detects ambiguity.

Why it failed: Frontier models suffer from severe meta-cognitive blindspots when dealing with interaction bugs. The baseline model confidently believes its first broken patch is correct, so it never experiences the doubt required to trigger an external consultation. Self-routing yielded an invocation rate near zero on the very cases that needed it.

3. The Native Static Detector Experiment

Hypothesis: Use lexical AST parsing and static regex triggers in the IDE/CLI to flag nested pointer events and inject the skill deterministically without LLM gating overhead.

Why it failed: Static detectors proved completely brittle across custom frameworks and abstractions. They triggered endlessly on standard benign patterns (e.g. nested buttons with proper delegation) while completely missing cross-component lifecycle leaks (e.g. uncancelled RAF loops, background tab listeners, or React Native gesture responders wrapped in hooks).

Disposition Record

Final Product Disposition

ARCHIVAL DISPOSITION DECISION • EXP-202609-ID
EFFECTIVE DATE: SEPTEMBER 2026
INTERACTION DOCTOR SKILL: DISCONTINUED
BENCHMARK & HARNESS: RETAINED AS RESEARCH ASSET
EMPIRICAL OBSERVATIONS: PRESERVED (90 RUNS)

Core Rationale: The benchmark demonstrated that modern frontier coding models already possess sufficient latent capability to diagnose and repair well-specified interaction bugs without domain-specific skill intervention. The specialized skill introduced a ~1.91× token cost penalty and a ~2.44× latency overhead without improving repair outcomes.

The benchmark itself, however, remains a uniquely rigorous instrument: it features private behavioral oracles, distinguishes source churn from functional repairs, isolates protocol compliance from actual bug fixes, and rigorously scores ambiguous intent. It is preserved for future evaluations of agent architectures.
