엔지니어링 사후 회고록 (Postmortem)

제품화가 실패한 이유: 3가지 아키텍처적 막다른 골목

초기 스모크 테스트에서 인터랙션 닥터를 상시 실행하면 결함 해결 이점 없이 비용만 두 배로 든다는 사실이 드러나자, 엔지니어링 팀은 스킬을 선별적으로 호출하기 위한 3가지 완화 아키텍처를 탐색했습니다. 그러나 3가지 모두 실패했습니다.

1. 범용 시맨틱 평가 게이트의 딜레마 (The Universal Semantic Eval Gate Problem)

가설: 무거운 스킬을 로드하기 전에, 유입된 태스크가 인터랙션 소유권 문제를 포함하고 있는지 판단하는 빠르고 저렴한 업스트림 분류기 프롬프트를 모델 앞에 배치한다.

실패 원인: 연쇄적 분류기(Cascading classifier)는 비대칭적 위험을 갖습니다. 게이트의 거짓 음성(False Negative) 확률이 10%만 되어도, 하류의 전문 스킬은 해당 태스크를 아예 볼 수 없습니다. 거짓 음성을 0으로 만들기 위해 게이트의 회상률을 넓히자 사실상 거의 모든 UI 수정 작업에서 게이트가 열려 전체 비용이 다시 1.9배로 회귀했습니다.

2. 모델의 자가 라우팅 실패 (The Self-Routing Failure)

가설: 기본 에이전트에게 간결한 도구/스킬 설명을 제공하고, 막히거나 모호성을 감지했을 때 모델 스스로 스킬을 호출하도록 한다.

실패 원인: 프론티어 모델은 인터랙션 버그를 다룰 때 심각한 메타인지적 사각지대(Meta-cognitive blindspot)를 겪습니다. 베이스라인 모델은 자신이 처음 제시한 잘못된 패치가 옳다고 확신하므로, 외부 자문을 요청하는 데 필요한 의심을 전혀 품지 않습니다. 자가 라우팅은 스킬이 가장 필요한 케이스에서 호출률이 0에 수렴했습니다.

3. 네이티브 정적 탐지기 실험의 한계 (The Native Static Detector Experiment)

가설: IDE나 CLI에서 어휘적 AST 파싱과 정적 정규식 트리거를 사용하여 중첩 포인터 이벤트를 감지하고, LLM 게이팅 오버헤드 없이 결정론적으로 스킬을 주입한다.
