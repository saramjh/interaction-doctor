# Interaction Doctor Benchmark (인터랙션 닥터 벤치마크)

[English](README.md) | [한국어](README.ko.md)

> **상태 공지: 스킬 제품화 중단(DISCONTINUED) &bull; 벤치마크 및 연구 자산 영구 보존(RETAINED)**  
> Interaction Doctor는 코딩 에이전트가 UI 인터랙션 소유권(ownership), 제스처 충돌, 생명주기(lifecycle) 결함을 진단 및 수정하도록 돕는 특화 스킬로 개발되었습니다.  
> 그러나 `claude-sonnet-5`를 대상으로 진행된 30개 케이스, 90회 실행의 대조 벤치마크 실험 결과, 본 스킬은 **기본 모델(Baseline) 대비 결함 수정 성공률을 전혀 개선하지 못했으며**(모든 군 19/19 성공), 오히려 **토큰 비용 약 1.91배**, **실행 지연 시간 약 2.44배**를 유발했습니다.  
> 이에 따라 Interaction Doctor는 **스킬 제품으로서의 개발 및 배포가 공식 중단**되었습니다.  
> 본 저장소는 특화 코딩 스킬의 실제 유용성을 검증하는 독립된 공개 벤치마크, 평가 하네스, 엔지니어링 회고록(postmortem)으로 전환되어 영구 보존됩니다.

## 핵심 실증 결과 요약

본 실험은 `claude-sonnet-5` (medium effort) 모델을 대상으로 총 30개 케이스를 3가지 실험 조건(군)에서 각각 격리 실행하여 총 90회의 유효 관측치를 수집했습니다:

1. **A군 (Baseline, 기본 모델):** 추가 스킬이나 특수 프롬프트 없이 순수 태스크 지시문만 제공.
2. **B군 (Generic Rigor, 일반 엄격 감사 프롬프트):** Interaction Doctor 고유 용어 없이 "면밀히 검토하고 엣지 케이스를 감사하라"는 일반 프롬프트만 추가.
3. **C군 (Doctor v1, 인터랙션 닥터 스킬):** 동결된 Interaction Doctor v1 스킬을 워크스페이스에 주입하고 스킬 프로토콜 준수 지시.

| 평가 지표 | 베이스라인 (A군) | 일반 감사 (B군) | 인터랙션 닥터 (C군) | 관측된 차이 및 해석 |
| :--- | :---: | :---: | :---: | :--- |
| **결함 수정 성공률 (명시적 결함 케이스)** | **19 / 19 (100%)** | **19 / 19 (100%)** | **19 / 19 (100%)** | **0% 개선** (완벽한 성능 동등) |
| **정상 케이스 무변경 유지 (NO-Op)** | 3 / 5 (60.0%) | 2 / 5 (40.0%) | 2 / 5 (40.0%) | 베이스라인이 불필요한 코드 수정이 적음 |
| **기능적 오탐 (False Positive)** | 0 / 5 (0.0%) | 0 / 5 (0.0%) | 0 / 5 (0.0%) | 모든 군이 정상 로직을 파괴하지 않음 |
| **임의 의도 추측률 (NEEDS_INTENT)** | 6 / 6 (100%) | 6 / 6 (100%) | 4 / 6 (66.7%) | 닥터가 2개 케이스(011, 016)에서 임의 수정을 멈춤 |
| **모호성 확인 중단 (Manual Review)** | 0 / 6 (0.0%) | 0 / 6 (0.0%) | 2 / 6 (33.3%) | 닥터에서 유일하게 관측된 긍정적 신호 |
| **기능 퇴행 (Regression)** | 1 / 30 (3.3%) | 1 / 30 (3.3%) | 0 / 30 (0.0%) | *독립적이지 않음:* 011번 케이스에서만 발생했으며, 닥터는 수정을 멈췄기 때문에 퇴행을 피한 것임 |
| **거짓 완료 주장 (False Closure)** | 0 / 30 (0.0%) | 1 / 30 (3.3%) | 0 / 30 (0.0%) | B군이 실패한 케이스에서 작업 완료를 허위 주장 |
| **키워드 진단 휴리스틱** | 14 / 19 (73.7%) | 18 / 19 (94.7%) | 18 / 19 (94.7%) | 키워드 포함 메타데이터일 뿐 실제 의미적 회상률이 아님 |
| **총 실행 비용 (30회 합계)** | **$3.2389** | **$3.4414** | **$6.1973** | **약 1.91배 비용 증가** |
| **회당 평균 비용** | 약 $0.1080 | 약 $0.1147 | 약 $0.2066 | 회당 +$0.0986 추가 지출 |
| **총 실행 시간 (Wall Clock)** | **848.2초** | **994.0초** | **2067.2초** | **약 2.44배 지연 시간 증가** |
| **회당 평균 실행 시간** | 약 28.3초 | 약 33.1초 | 약 68.9초 | 회당 +40.6초 추가 지연 |
| **총 도구 호출 횟수** | **138회** | **137회** | **212회** | **약 1.54배 도구 호출 증가** |

### 핵심 분석 결론

1. **수정 능력의 개선 부재:** 최신 프론티어 모델은 특화된 외부 스킬 없이도 잘 정의된 인터랙션 결함을 진단하고 수정할 수 있는 잠재 능력을 이미 갖추고 있습니다.
2. **막대한 리소스 낭비:** 닥터 스킬은 재귀적 소유권 감사 루프로 인해 토큰 비용을 1.91배, 실행 시간을 2.44배 급증시켰습니다.
3. **제한적인 모호성 감지 신호:** 요구사항이 불명확한 케이스 중 2건(`case-011`, `case-016`)에서만 닥터가 임의로 기획을 결정하지 않고 사용자에게 되묻는 올바른 동작을 보였습니다.
4. **퇴행 0건의 진실:** A군과 B군에서 발생한 유일한 퇴행은 `case-011`이었습니다. 닥터가 퇴행을 피한 유일한 이유는 문제를 고치려다 실패한 것이 아니라, 정책 미확정을 감지하고 수정을 중단했기 때문입니다.

## 벤치마크가 독립 연구 자산으로 가치 있는 이유

스킬 자체는 폐기되었지만, 본 벤치마크는 코딩 에이전트 평가를 위한 고유한 가치를 지닙니다:

- **스킬의 인과적 효용성 측정:** 특화 스킬이 모델에 실질적인 도움을 주는지, 아니면 단순 토큰 낭비인지 엄격히 판별합니다.
- **용어 준수와 실제 해결 능력의 분리:** 에이전트가 스킬 용어를 읊었는지가 아니라, 런타임 비공개 테스트 오라클을 통과했는지만 평가합니다.
- **단순 코드 변경(Churn)과 실제 기능 변경의 구별:** 주석 추가나 서식 변경 같은 의미 없는 수정을 기능적 해결과 엄격히 분리합니다.
- **모호한 기획에 대한 독단적 추측 채점:** 요구사항이 불완전할 때 임의로 결정을 내려 코드를 왜곡하는 에이전트를 감점합니다.
- **포괄적인 인터랙션 위상학:** 단일 요소 제스처 충돌, 다자간 이벤트 경쟁, 백그라운드 전환/언마운트 생명주기 누수, 비동기 상태 역전 등을 망라합니다.

## 재현 및 데이터 무결성 검증

### 1. 쇼룸 데이터 무결성 검증
쇼룸에 표시되는 모든 통계가 동결된 원천 결과와 100% 일치하는지 확인:
```bash
python3 scripts/validate_showroom_data.py
```

### 2. 채점기 자체 검증 실행
자동 채점기가 정답 픽스처에 대해 올바르게 판정하는지 검증:
```bash
python3 benchmark/graders/grade_run_selftest.py
```

### 3. 실험 동결 해시 검증
모든 핵심 실행 파일과 픽스처가 동결된 SHA-256 해시와 일치하는지 확인:
```bash
python3 benchmark/design/verify_experiment_freeze.py
```

## 중요한 실험적 한계점

1. **사전 적격성 판정 유예 (HOLD):** 90회 정규 실행 전, 모델이 프롬프트 부록의 일부 진단 프로브를 실행하지 않아 사전 적격성 게이트가 `HOLD` 상태였습니다. 이는 인프라 결함이 아닌 모델의 단순 프로브 지시 불이행으로 판명되어 공식 유예(waiver) 하에 정규 실험이 수행되었습니다.
2. **재시도 이력:** 001~014번 케이스는 1차 실행(`run-01`)에서 정상 완료되었습니다. 015~030번 케이스는 Claude API 429 한도 초과로 인해 세션 리셋 후 3차 실행(`run-03`)에서 완료되었습니다. 결과를 좋게 만들기 위해 성공한 케이스를 재실행한 적은 없습니다.
3. **미모델링 케이스 부재 (`UNMODELED = 0`):** 30개 케이스는 모두 모델링 가능한 표준 인터랙션 영역을 다룹니다. 따라서 본 벤치마크는 에이전트의 미지원 하드웨어 감지 능력을 대변하지 않습니다.
4. **기술적 파일럿 성격:** 각 군당 $n = 30$, 1회 반복 실행으로 구성된 탐색적 파일럿입니다. 스킬의 경제적 실효성 결여를 증명하기에는 충분하나, 통계적 가설 검정(p-value)을 주장하지는 않습니다.
