## 0. 이 문서의 사용법

이 문서는 계획서가 아니라 **작업 지시서**입니다.
각 주차는 산출물 하나로 끝나고, 끝날 때마다 **계속할지 접을지 판단하는 게이트**가 있습니다.

목표가 스타이므로 우선순위는 다음 순서로 고정합니다.

```
1. 공유 가능성   (이걸 남에게 보여주고 싶은가)
2. 즉시 이해도   (10초 안에 뭔지 아는가)
3. 설치 마찰     (한 줄인가)
4. 정확성        (틀리면 신뢰가 무너짐)
5. 완결성        ← 가장 낮음. 완성도보다 공개가 먼저
```

**5번을 1번보다 앞세우는 순간 이 프로젝트는 실패합니다.** 스타는 완성도가 아니라 공유 가능성이 만듭니다.

## 1. 프로젝트 확정 사항

### 이름
`interaction-doctor`

증상 → 진단 → 처방 구조와 이름이 일치합니다. `interaction-lint`는 폐기합니다. 린터가 아니고, 린터로는 핵심 규칙이 정적 판정되지 않습니다.

- GitHub: `interaction-doctor/interaction-doctor`
- npm: `interaction-doctor`
- 스킬명: `interaction-doctor`

### 한 줄 정의 (README 첫 문장 확정)

> **다른 스킬은 UI를 만드는 걸 돕습니다. 이건 인터랙션이 깨졌을 때 고치는 걸 돕습니다.**

영문:
> Other skills help agents *build* UI. This one helps them *fix* interactions that broke.

### 차별화 좌표

프론트엔드 스킬 생태계는 이미 포화 상태입니다. frontend-design, UI UX Pro Max, motion-framer, shadcn MCP 등 "AI에게 UI 잘 시키는" 스킬이 넘칩니다.
**생성 품질 향상으로 포지셔닝하면 묻힙니다.** 좌표는 하나입니다.

```
생성 보조 (포화)  ←──────────────→  디버깅 보조 (비어 있음)
                                        ↑
                                   여기만 점유
```

### 3층 구조

| 층 | 형태 | 대상 | 주 기능 |
|---|---|---|---|
| L1 충돌 매트릭스 | 마크다운 | 전원 | 스타를 만드는 자산 |
| L2 Skill | Agent Skill | 바이브코더/주니어 | 지식 주입 + 증상 진단 |
| L3 doctor | dev 전용 npm 패키지 | 시니어 | 실행해서 사실 관측 |

L1이 유입, L2가 설치, L3가 시니어 채택입니다.
**L3는 조건부입니다.** W0 검증 결과가 정하며, 여기서 일정이 2주와 6주로 갈립니다.

## 산출물

미완성 칸은 `🚧 contributions welcome`로 남깁니다.
**미완성을 숨기지 마십시오.** 빈칸은 기여 유입구이고, 이슈가 열리는 지점입니다.

## 각 칸의 고정 포맷

```markdown
### C10 — Drag ↔ Scroll

**증상**
- 모바일에서 드래그하면 페이지가 같이 스크롤된다
- 리스트를 스크롤하려는데 항목이 끌려온다

**원인**
브라우저 스크롤은 컴포지터 스레드에서 즉시 시작된다.
JS의 preventDefault로는 이미 늦다. touch-action으로
사전에 선언해야 한다.

**해소**
```css
.draggable-item { touch-action: pan-y; }  /* 수직 스크롤 유지 */
.canvas-surface { touch-action: none; }   /* 전면 차단 */
```
+ 8px 이동 임계값을 넘기 전까지 드래그를 활성화하지 않는다
+ `setPointerCapture`로 스트림을 고정한다

**우선순위 규칙**
```
임계값 미만 → 판정 보류 (둘 다 후보)
수직 우세   → Scroll 승, Drag 후보 폐기
수평 우세   → Drag 승, touch-action이 Scroll 차단
```

**검증 방법**
실기기에서 항목을 대각선으로 천천히 드래그.
둘 다 동시에 움직이면 실패.

**근거**
CSS `touch-action` (W3C Pointer Events Level 2)
```

## SKILL.md 트리거 설계 — 가장 중요한 한 줄

**`description`이 스킬의 성패를 가릅니다.** 에이전트는 이 문장만 보고 로드 여부를 정합니다.
너무 좁으면 안 뜨고, 너무 넓으면 엉뚱하게 떠서 방해가 되고, 그러면 제거당합니다.

```yaml
---
name: interaction-doctor
description: >
  터치·포인터 인터랙션이 의도대로 동작하지 않을 때 진단하고 수정한다.
  드래그가 스크롤과 충돌하거나, 모바일에서만 동작이 다르거나,
  탭·롱프레스·스와이프·핀치가 서로 간섭할 때 사용.
  드래그·스와이프·롱프레스·핀치·재정렬·캔버스 조작을 새로
  구현할 때도 사용.
---
```

앞 두 문장이 디버깅, 마지막이 예방입니다. 순서가 중요합니다.

## SKILL.md 본문 골격

```markdown
# Interaction Doctor

## 사용 순서
1. 사용자가 증상을 말하면 → `references/symptoms.md`에서 매칭
2. 같은 요소에 제스처가 2개 이상이면 → `references/conflicts.md`
3. 새로 구현하면 → `references/recipes.md`

## 진단 우선 규칙
추측해서 고치지 않는다. 증상표에서 원인이 특정되지 않으면
아래 세 가지를 먼저 확인하고 사용자에게 묻는다.

1. 실기기에서 발생하는가, 데스크톱 반응형 모드에서만인가
2. 해당 요소의 computed touch-action 값은 무엇인가
3. 같은 요소에 붙은 이벤트 핸들러 전체 목록은 무엇인가

## 절대 하지 않을 것
- pointermove에서 preventDefault로 스크롤을 막으려는 시도
  (컴포지터 스레드에서 이미 시작됨. touch-action을 쓸 것)
- mouse/touch 이벤트를 pointer와 병용
- setTimeout만으로 롱프레스 구현
- 임계값 없이 pointerdown에서 즉시 드래그 활성화

## 완료 전 자가 점검
- [ ] touch-action이 명시적으로 선언됨
- [ ] pointercancel이 처리됨
- [ ] 타이머가 move·up·cancel 모든 경로에서 해제됨
- [ ] 키보드로 동일 작업 가능 (WCAG 2.5.7)
- [ ] 이벤트 계통을 혼용하지 않음
```

## symptoms.md — 25개 항목

포맷:

```markdown
## "모바일에서 드래그하면 화면이 같이 움직여요"

**원인** touch-action 미선언
**확인** DevTools에서 getComputedStyle(el).touchAction === 'auto'
**수정** 드래그 요소에 touch-action: pan-y (또는 none)
**부작용** none은 해당 영역 스크롤을 완전히 막음. 컨테이너가
          스크롤되어야 하면 pan-y를 쓸 것
**관련** C10
```

# W4 — Inspector 데모 (5일)

**트래픽 유입구.** 스타 관점에서 가장 효율 높은 단일 산출물입니다.
문제를 설명하지 않고 **보여줍니다.** 아무것도 설치하지 않고 링크만 열면 됩니다.

## 사양

정적 사이트 1개 (Vite + TS). `interaction-doctor.dev` 또는 GitHub Pages.

```
┌─────────────────────────────────────┐
│ [Drag in Scroll ▾]  touch-action:   │
│                     ( auto | pan-y )│  ← 실시간 토글
├─────────────────────────────────────┤
│  Item A                             │
│  Item B  ← 여기서 드래그              │
│  Item C                             │
├─────────────────────────────────────┤
│ pointer  touch   id=2               │
│ 182ms    24.2px   83°               │
│                                     │
│ 후보    TAP · DRAG · SCROLL          │
│ 승자    DRAG                         │
│ 취소    SCROLL (touch-action)        │
│         TAP (거리 > 8px)             │
│                                     │
│ 0ms    pointerdown                  │
│ 16ms   pointermove  1.2px           │
│ 182ms  pointermove  24.2px → DRAG   │
└─────────────────────────────────────┘
```

## 필수 기능 (이것만)

1. `touch-action` **실시간 토글** — 켜고 끄면서 차이를 직접 체감. **가장 중요한 기능**
2. 이벤트 로그 + 누적 거리/시간/각도
3. 임계값 기준선 표시 (8px / 500ms / 300ms)
4. `pointercancel` 발생 시 시각적 강조
5. 시나리오 5개 탭

## 시나리오

```
Drag in Scroll      ← 기본값. 가장 강력
Tap vs Long Press
Swipe vs Scroll
Drag vs Selection
Pinch vs Page Zoom
```

## 만들지 않을 것

- 로그인, 저장, 공유 기능
- 모바일 최적화된 화려한 UI
- 코드 생성 기능

**Inspector는 도구가 아니라 논증입니다.** 기능을 늘리면 논점이 흐려집니다.

# W5–W6 — doctor (조건부, 10일)

**W0의 V2 결과가 "월 2회 이상"일 때만 만듭니다.**
시니어의 결핍은 지식이 아니라 검증입니다. 이미 `touch-action`을 알지만 **실기기 확인을 안 합니다.** 그 갭은 스킬로 안 메워집니다.

## 형태

```bash
npm i -D interaction-doctor
```

```jsx
{import.meta.env.DEV && <InteractionDoctor />}
```

## 출력 — 에이전트가 읽을 형식으로

```
[interaction-doctor] 2 issues

▸ .card-item
  observed:  pointerdown → pointermove(24px) → pointercancel
  computed touch-action: auto
  listeners: pointerdown, pointermove, pointerup
  
  ✗ touch-action 미선언 (스크롤 컨테이너 내 드래그)
    → .card-item { touch-action: pan-y }
  ✗ pointercancel 핸들러 없음
    → 취소 시 드래그 상태가 복구되지 않음
  
  참조: C10, symptom #1, #6
```

**이 출력을 그대로 에이전트에 붙여넣으면 한 번에 고쳐지는 것**이 설계 목표입니다.
왕복 5회를 1회로 줄이는 지점이 여기입니다.

## 탐지 방식 — 정적 분석이 아니라 런타임

| 검사 | 방법 | 정확도 |
|---|---|---|
| touch-action | `getComputedStyle(el).touchAction` | **정확** (캐스케이드 해소됨) |
| 리스너 등록 | 로드 시점 `addEventListener` 후킹 | 높음 |
| 상태 미복구 | `pointercancel` 주입 후 transform 잔존 확인 | 높음 |
| 임계값 부재 | 관측된 최소 이동거리 통계 | 중간 |
| 키보드 대안 | 포커스 + 방향키 후 DOM 변화 관측 | 중간 |

정적 분석으로 결정 불가능했던 항목들이 런타임에서는 대부분 정확해집니다.
접근성 업계도 WCAG 2.5.7은 정적 분석으로 탐지 불가하며 수동 검토가 필요하다고 정리하고 있습니다. 런타임 관측은 그 사이를 메우는 위치입니다.

## 정확도 기준

**오탐 0을 목표로 합니다.** 확신 없는 항목은 보고하지 않습니다.
개발 콘솔에 오탐이 뜨는 도구는 즉시 제거됩니다.

# W7 — 측정 (5일)

README 헤드라인 숫자를 만듭니다.

## 지표를 바꿉니다

위반 건수가 아니라 **왕복 횟수와 토큰**입니다. 대상 사용자에게 100배 잘 읽힙니다.

```
디버깅 왕복    5.2회 → 1.4회
토큰 소비      48,000 → 15,000  (69% 감소)
해결 시간      23분 → 6분
```

## 방법

결함이 심어진 컴포넌트 10개를 만듭니다. 각각 증상 하나씩.

```
evals/broken/
├── 01-drag-scroll-conflict/
├── 02-stuck-after-cancel/
├── 03-longpress-not-firing/
...
```

각 케이스에 대해 **증상 문장만** 에이전트에 주고, 해결될 때까지 왕복 횟수를 셉니다.

```
조건 A: 스킬 없음
조건 B: 스킬 있음
모델:  2종
반복:  3회
총:    10 × 2 × 2 × 3 = 120 세션
```

## 게이트

| 왕복 감소율 | 판정 |
|---|---|
| 50% 이상 | 헤드라인으로 사용 |
| 30~50% | 사용하되 조건 명시 |
| 30% 미만 | **숫자를 쓰지 않음.** 스킬 개정 후 재측정 |

**숫자가 약하면 쓰지 마십시오.** 부풀린 수치는 검증당하고, 걸리면 프로젝트가 끝납니다.
