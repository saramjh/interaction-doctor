# evals/trigger-tests/cases.md — 스킬 트리거 21개 케이스 원문

이 21개 문장은 `interaction-doctor` 스킬의 `description`이 실제로
올바르게 트리거되는지 확인하기 위해 쓴 것이다 — 컴포넌트 이름,
"트리거 테스트"라는 메타정보, 채점 기준 어느 것도 문장 안에 없다
(`evals/subjects/*/request.txt` 작성 규칙과 동일한 원칙). 각 문장은
독립된 새 세션(서브에이전트)에 그대로만 전달됐다.

이 파일은 원문 이관만 한다 — 판정 결과(트리거 여부, 정확도)는
`docs/stats.md` §3에 이미 정리돼 있으므로 여기서 중복 기록하지
않는다. 재현하려면 아래 문장을 새 세션에 그대로 붙여넣고, 응답이
`symptoms.md`/`recipes.md`/`platform.md`/`architecture.md`/
`common-pitfalls.md` 중 하나라도 실제로 Read/Grep했는지로 판정한다
(`SKILL.md` 자체는 Skill 도구 자동 반환이라 이 5개에 포함 안 함).

## T1~T11 — 반드시 트리거되어야 하는 요청 (기대 컴포넌트/유형)

**T1** (reorderable-list)
> 드래그해서 순서 바꾸는 리스트 만들고 있는데, 롱프레스로 해야 하나요 아니면 핸들 아이콘을 넣어야 하나요?

**T2** (swipe-actions)
> 카카오톡처럼 리스트 항목을 스와이프하면 삭제 버튼 나오게 하고 싶은데, 끝까지 밀면 바로 삭제되게 해야 하나요 아니면 버튼만 노출해야 하나요?

**T3** (bottom-sheet + 오염방지 유형 B)
> 바텀시트 안에 긴 리스트를 넣었는데, 리스트를 아래로 스크롤하려고 하면 리스트가 아니라 시트 전체가 닫혀버려요

**T4** (carousel)
> 이미지 캐러셀을 만드는데 스냅되게 해야 할지 자유 스크롤로 둬야 할지 모르겠어요

**T5** (CONFLICTS.md#C13 — Scroll↔Pinch)
> 세로로 스크롤되는 페이지 안에 있는 이미지에 핀치 줌을 추가했는데, 손가락으로 확대하려고 하면 페이지가 같이 스크롤돼요

**T6** (multi-select)
> 사진 여러 장을 길게 눌러서 다중 선택하는 기능을 넣고 싶은데 어떻게 시작해야 하나요

**T7** (context-menu, CONFLICTS.md#C6)
> 리스트 항목을 길게 누르면 커스텀 메뉴가 뜨게 했는데, (모바일에서) 브라우저 기본 메뉴가 같이 떠요

**T8** (tab-swipe)
> 하단 탭바를 좌우로 스와이프해서 넘길 수 있게 만들고 싶어요

**T9** (side-drawer + 오염방지 유형 C)
> 사이드 메뉴를 화면 왼쪽 가장자리에서 스와이프해서 열리게 만들었는데, iOS에서 뒤로가기 제스처랑 자꾸 겹쳐요

**T10** (오염방지 유형 A — 롱프레스 3중 충돌)
> 리스트 항목 하나에서 롱프레스로 재정렬도 되고 길게 누르면 다중선택 모드도 켜지게 하고 싶은데, 둘 다 롱프레스라 뭐가 열려야 할지 모르겠어요

**T11** (CONFLICTS.md#C10 — Drag↔Scroll, 일반형)
> 세로 리스트에서 항목을 드래그하니까 페이지 스크롤이 같이 움직여요

## N1~N10 — 트리거되면 안 되는 요청 (이 스킬과 무관)

**N1** (JSON 파싱, 인터랙션과 무관)
> 이 API 응답 JSON을 파싱해서 배열로 바꿔줘

**N2** (폼 검증, 인터랙션과 무관)
> 회원가입 폼 유효성 검사 로직 짜줘

**N3** (다크모드 팔레트, 인터랙션과 무관)
> 다크모드 색상 팔레트 골라줘

**N4** (SQL 최적화, 인터랙션과 무관)
> 이 SQL 쿼리 최적화해줘

**N5** (키보드 단축키, 터치/포인터 충돌 없음)
> 이 버튼에 Ctrl+S 단축키 바인딩해줘

**N6** (데스크톱 우클릭 — 함정: `contextmenu`라는 이벤트 이름은 겹치지만 터치/포인터 충돌이 애초에 없음)
> 데스크톱에서 마우스 우클릭하면 커스텀 컨텍스트 메뉴가 뜨게 해줘

**N7** (포커스 트랩, 인터랙션과 무관 — 키보드 접근성)
> 모달 안에서만 Tab 키가 순환되는 focus trap 만들어줘

**N8** (아코디언 애니메이션, 제스처 충돌 없음)
> 아코디언 접었다 펴지는 애니메이션 부드럽게 해줘

**N9** (독립 핀치줌 — 함정: T5와 표면적으로 비슷하지만 스크롤 컨테이너/다른 콘텐츠가 없어 충돌 자체가 성립 안 함)
> 이미지 뷰어 화면 전체를 고정 크기 캔버스로 쓰고 그 안에서만 핀치 줌 되게 해줘 — 페이지 자체는 스크롤 안 되고 캔버스 밖에 다른 콘텐츠도 없음

**N10** (무한 스크롤, 인터랙션 충돌과 무관 — 데이터 로딩 패턴)
> 리스트에 무한 스크롤(infinite scroll) 구현해줘

## 참고

- 최초 실행 결과, N6 description 수정 후 재실행 결과, 최종 정확도
  (미탐 0/11, 오탐 1/10 — N9만 남음, N6은 SKILL.md description
  수정으로 해소)는 `docs/stats.md` §3 "스킬 트리거 정확도"에 있다.
- N6/N9 오탐의 원인은 스킬의 `description`이 아니라
  `.claude/CLAUDE.md`의 프로젝트 전역 규칙이 Skill 도구를 거치지
  않고 직접 발동한 것이었다 — 자세한 내용도 `docs/stats.md` §3.
- 각 케이스는 독립된 새 세션에서 실행해야 한다 — 이전 케이스의
  컨텍스트가 다음 케이스에 영향을 주면 판정이 오염된다.
